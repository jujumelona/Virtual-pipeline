# 완성 원화 → 2D VTuber 자동 파츠 분리 기준 (2026-10-16)

> **작업 단계 구분:** 이미지 생성 AI는 완성 정면 `outputs/master.png`와 다각도·표정 참고 이미지를 만든다. **See-through/Colab이 정면 이미지에서 파츠를 실제로 추출하고 PSD로 구성한다.** PSD2Live는 그 뒤에 리깅한다. 이미지 생성 AI에 See-through나 PSD 리깅을 맡기지 않는다.

## 공식 원칙

1. Live2D 공식 소재 분리 튜토리얼: 속눈썹·홍채·흰자, 눈썹, 코, 얼굴 윤곽·귀, 입 위/아래 라인·입안, 목·몸통·상완·전완·손, 전신 다리를 분리하고 가려진 부분을 추가 작화한다. **모든 스타일에 동일한 고정 레이어 수 규정은 없다.**
2. PSD2Live 공식 사양: **EYEWHITE/IRIDES/EYELASH는 서로 다른 분류**이며 윗속눈썹은 아랫눈꺼풀과 합치지 않는다. 완전히 열린 입안은 별도 제공해야 한다. 가려진 입안을 닫힌 입 하나에서 추측 생성할 수 없다. 좌우는 **캐릭터 기준**이며 화면 왼쪽과 반대다.
3. 라인과 채색은 동일한 움직임을 보이면 최종 PSD에서 하나의 RGBA ArtMesh 레이어로 합친다. 별도 움직이는 파츠끼리는 합치면 안 된다.

## 2D BODY 모델의 분리 목표 (정면에서 실제 ArtMesh가 필요한 파츠)

| 대상 | 필수 개별 분리 | 선택적 추가 분리 | 검수 이유 |
|---|---|---|---|
| 얼굴 | `face` 피부·윤곽, `nose`, `ear.left/right` | 볼터치·별도 피부 그림자 | 회전 시 코·귀·턱·가림이 같이 움직여야 함 |
| 양쪽 눈 | 각 눈의 `white` / `iris` / `upper_lash` | 동공, 하이라이트, 눈꺼풀 피부, 아래 속눈썹, 눈꼬리 | 시선은 홍채·동공만; 머리 회전은 눈 전체 |
| 눈썹 | `brow.left/right` | 표정용 추가 눈썹 | 좌우 표정 독립 |
| 입 | `mouth.open` (완전 열린 입안 그림)와 입술·닫힌 상태를 표시하거나 변형할 구성 | 윗입술/아랫입술, 치아·혀 | 닫힌 정면 입 원화만으로 입안을 자동 복원할 수 없음 |
| 목 | `neck` | 필요한 가림·목 뒷면 보충 | 턱 아래·어깨 안쪽의 숨은 색상과 선이 이어져야 함 |
| 몸통 | `torso` | 어깨 좌우, 분리된 기본 가림 복장 | 팔 뒤의 몸통이 실제로 그려져야 함 |
| 양팔 | 각 `arm.{left/right}.upper`, `arm.{left/right}.forearm`, `hand.{left/right}` | 손가락, 손목 장식 | 어깨·팔꿈치·손목의 회전·겹침 경계 보존 |
| 전신 추가 | 골반, 좌/우 허벅지, 좌/우 종아리, 좌/우 발 | 무릎/발목 별도 그림·신발 | 전신 움직임에 필요한 관절 분리 |

**주의:** 위 BODY 기준은 본 프로젝트의 모델 기능 요구에 대한 것이며 Live2D 공식의 '21장 고정 규격'이 아니다. 눈 흰자/홍채/윗속눈썹은 공식 및 현재 PSD2Live 명세가 직접 강조한다. 별도 동공·하이라이트는 각각 별도 움직임이 필요할 때만 분리하며 같은 이동을 한다면 홍채와 합칠 수 있다.

## 추가 자산별 분리

- **헤어**: `hair.back`(뒷머리), `hair.front`(앞머리/앞쪽 가닥), `hair.side.left/right`, 독립적으로 흔들릴 긴 머리 묶음·잔머리·장식. 움직임이 같은 모발을 불필요하게 가닥 단위로 모두 절단하지 않는다. 머리 아래 가려진 뒤쪽은 추가 작화해야 한다.
- **의상**: `outfit.front`와 실제 뒤쪽에 보일 `outfit.back`, `sleeve.left/right`, 독립적으로 움직이는 칼라·리본·밑단·치마. **몸통에 붙어 있는 봉제선·소매 기점은 유지**, 소매 끝과 천 끝만 필요한 방향으로 변형한다. 소재 무늬·정적인 박음질은 같은 천 파츠에 남긴다.
- **액세서리**: 실제 디자인에 존재하는 귀걸이 좌/우, 목 장신구, 머리핀, 리본, 물리 흔들림을 갖는 부분만 분리한다. 고정된 장식은 부모 의상·머리 파츠에 포함 가능. 부착점과 가려지는 부분 명확히.
- **바스트업**: 실제 화면에 보이는 얼굴·목·어깨·상완·전완·손을 기준으로 하며 전신 부위 생성 금지. **전신**이면 다리·발과 허리 아래 부착부를 추가.
- **3D 모델**: 2D RGBA 파츠 분리가 아니라 메시·재질·본·스키닝 기반 구조를 별도로 써야 하므로 이 2D 목록을 3D의 메시 제작 규정으로 적용하지 않는다.

## 절대로 잘못 분리하지 말 것

1. **전체 눈 = IRIDES 금지:** `eyes` 또는 `eye.left` 같은 굵은 영역만 있으면 흰자·홍채·속눈썹이 별개라는 증거가 아니다. **복합 눈 텍스처를 홍채 드라이버에 붙이면 눈이 통째로 움직인다.**
2. **좌우 혼동 금지:** 화면 왼쪽이 캐릭터 오른쪽일 수 있다. 원본에 방향 근거가 없다면 `l/r`를 추측해 성공 표시하지 않는다.
3. **투명 틈 금지:** 마스크로 잘린 턱·목·겨드랑이·상완·눈 흰자·뒷머리의 숨은 RGB를 단순히 비우지 않는다. 필요한 구간은 실제 같은 스타일로 재작화한다.
4. **원화 없는 입안/측면을 분리 성공으로 표시 금지:** 정면 하나에 안 보이는 영역은 분할만으로 만들어지지 않는다. 열린 입 참고·측면 참고는 원화 생성 단계에서 별도로 준비한다.
5. **PSD 레이어 != 파츠 폴더 != 디포머:** 서로 다르다. 이름이나 레이어 개수로 운동 품질을 판정하지 않는다.

## 현재 코드 기준 확인된 결함과 대응

- See-through의 NF4 1차 추론은 여러 영역의 PSD를 만들고, 후속 `SemanticSam`은 **19개 coarse class**(그중 눈은 단일 `eyes` 라벨)를 사용한다. 19종 마스크를 실행했다고 양눈 흰자·홍채·윗속눈썹이 독립된 것은 아니다.
- 종전 `tools/vts_psd2live_names.py`는 `eye` 또는 SAM `eyes`를 `irides`로 매핑할 수 있었다. 이는 실제 이미지 분리 없이 잘못된 홍채 리깅을 유발하는 논리 오류다. 수정하여 **모호한 눈은 홍채로 분류하지 않는다.**
- `tools/vts_part_separation_contract.py`에서 출력 레이어명을 근거로 BODY·HAIR·OUTFIT·ACCESSORY의 역할 목록을 대조한다. `build_artwork_package`가 `metadata/part_separation_audit.json`을 결과 ZIP에 기록한다.
- 이 검사도 **라벨의 존재만 보는 1차 진단**이다. 실제 한 레이어가 독립 RGBA를 갖는지, 숨은 그림이 충분한지, 관절이 올바른지, 네이티브 MOC3 키폼이 정상이냐는 **별도 픽셀/포즈 검증이 반드시 필요**하다.
- `metadata/part_separation_audit.json`의 `missing_or_unproven_roles`는 자동으로 잘라졌다고 가정할 수 없는 부위다. 이 목록을 보고 **필요한 부분만** 더 세밀하게 분리·보정하거나, 숨은 원화가 원본에 없으면 원화 단계로 다시 요청해야 한다.

## 실제 제작 경로

`outputs/master.png` → **See-through NF4 / 원본 PSD 분해** → **좌우 분리·SemanticSam 19종 후보 처리** → **필요한 세부 파츠만 추가 분할·숨은 색 복원** → **각 레이어 의미 확인 + 좌우/마스크/캔버스 점검** → `PSD2Live` → 네이티브 MOC3 포즈 검사.

**미구현:** SAM19의 복합 눈에서 매번 신뢰 가능한 홍채·흰자·윗속눈썹을 **자동 추가 분리**하는 정밀 단계, 닫힌 입의 숨은 열린 입 재작화, 측면 참고 원화의 네이티브 키폼 자동 연결. 현재 구현/시험하지 않은 기능을 완료로 기록하지 않는다.
