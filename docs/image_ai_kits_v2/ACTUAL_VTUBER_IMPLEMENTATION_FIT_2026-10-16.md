# 이미지 생성 ZIP 24개 → 실제 버추얼 구현 적합성 조사

2026-10-16 (KST) · 코드/아트 계약 직접 검토 · **실제 생성 캐릭터 또는 native pose 캡처를 대신하는 검증이 아님**

## 결론

**합격 가능한 원화 입력 계약**과 **실제로 동작하는 아바타/옆모습**을 분리해 평가해야 한다. 24개 ZIP은 이제 구도·자산 역할·진짜 목 가림 피부 요구를 명시하지만, 참조 그림 자체를 네이티브 좌우 머리 회전으로 변환하는 자동 구현은 없다. 따라서 **90° 옆모습까지 완성**을 주장할 수 없다.

## 옆얼굴/목 직접 체크

1. **정면 BODY 픽셀:** 얼굴 `face.png` 아래에서 목 `neck.png`가 턱의 아래쪽 실제 알파 영역에 겹쳐야 한다. 목을 턱밑에서 자르면 얼굴 각도 X/Y/Z가 변할 때 피부 구멍이 생긴다. 목의 상단은 공식 Live2D 원화 가공 예제처럼 입 근처까지 가려진 피부로 연장한다.
2. **목뿌리–몸통 픽셀:** 목 끝을 몸통 상부에 겹쳐 그리며, 알파 영역은 선으로 접하기만 해서는 안 된다. 원래 그림에 없던 피부 연결을 참고용 `reference_views/neck_underpaint.png` 한 장만 그려 대체하지 않는다.
3. **좌우 약 45°:** `head_three_quarter_L/R.png`에는 눈·코·입·턱·귀의 실제 투시 차와 턱 뒤 목뿌리–어깨 연결을 포함한다. 얼굴 폭만 늘이거나 머리만 수평 이동하면 안 된다.
4. **좌우 90°:** `head_profile_L/R.png`는 진짜 측면 형태 기준이다. 귀 뒤쪽과 앞쪽의 앞뒤 위치, 한쪽 눈이 가려지는 양, 코·입·턱의 실루엣, 어깨·목 측면을 명확히 만든다. **이 파일은 PSD2Live의 -45..45° 파라미터와 연결되지 않는다**. 90° 네이티브 구현이 필요하면 별도 키폼·교체 파츠·추가 리깅을 만들어야 한다.
5. **올려보기/숙이기:** 턱 밑의 실제 보이는 피부 면적이 변화하고 목에 겹치거나 감춰지는 부분도 바뀐다. `head_pitch_up/down.png`가 아니라 실제 원본 `neck.png`의 숨은 픽셀도 이 동작에 대응해야 한다.
6. **헤어/의상:** 옆머리 모근은 귀 뒤, 뒤통수 헤어는 목 위를 덮거나 뒤로 지나간다. 옷깃·양소매는 목–어깨 회전과 같은 캔버스 앵커를 사용한다. 헤어·의상 PNG 안에 BODY 얼굴/목을 재작화하지 않는다.
7. **파일 크기/축:** 모든 2D 전·3/4·옆·상하 기본 참고 그림은 `outputs/master.png`와 같은 크기와 척도를 유지한다. 따로 클로즈업한 그림은 참고 자료로는 쓸 수 있어도 위치가 다른 키폼의 원화와 동일하게 취급하지 않는다.
8. **표정:** 실제 PSD2Live RigBuilder는 `mouth close` / `mouth open` 불투명도 전환, 치아/혀 페이드, 눈 흰자 마스크와 홍채/윗속눈썹 분리를 지원한다. 단, 이미지 AI가 만든 입 내용의 위치·선화와 실제 구현되는 중립 표정이 일치하는지는 네이티브 렌더로 직접 확인해야 한다.

## 구현 수정 기록

- 24 ZIP × 14개 문서에 `VTUBER_SIDE_NECK_RIG_ACCEPTANCE_V1` 추가: 옆/뒤 연결, 숨은 목 픽셀, 참조와 실물 키폼의 차이.
- `tools/vts_authored_part_art.py`: 무의미한 중복 불능 코드 제거, 작성된 BODY의 **턱–목·목–몸통 실제 알파 중첩** 수치가 충분하지 않으면 PSD 조립 전에 거부.
- `tools/vts_source_only_pack.py` + `tools/vts_multiview_runtime.py`: 측면·3/4·피치 비교 그림이 정면 마스터와 캔버스 치수가 다른 경우 거부; 참고 시점/실제 키폼 미연결 보고 유지.
- `notebooks/VTuber_Finished_AI_ZIP_All_Modes.ipynb`: Inochi2D 원화에 `part_art/`가 있으면 See-through로 다시 분리하지 않고 원본 작성 PNG를 Inochi PSD/메시 생성에 전달.
- `vtuber_pipeline/two_d/keyforms.py`: Inochi 목 메시에서 머리 X/Y/Z 움직임의 가중치를 목 윗부분 1, 목 아래 0으로 완만히 줄여 목뿌리를 몸통 쪽에 고정. 이것은 90° 기하학이나 Inochi 네이티브 포즈 합격 증거가 아니다.
- `tools/vts_native_moc_pose_worker.py` / `tools/vts_native_pose_integrity.py`: 기존 30° 검사 외에 **±45° 머리 요**와 **요+피치 복합** 실제 MOC3 렌더링 체크 추가.
- `tools/vts_multiview_runtime.py`: 실제 네이티브 모델 ±45°와 90° 참고 아트를 동시에 보는 검수 이미지를 만들되 서로 같은 각도로 속이지 않음.
- ZIP 바이너리 24개는 GitHub API를 통한 직접 원문·재압축 편집으로 교체했으며 배포를 CI에 맡기지 않았음.

## 평가 한계 및 실물 완료 조건

- **원화 자체:** 실제 이미지 AI 결과 ZIP은 아직 제공되지 않아 신체 형태, 캐릭터 스타일 일관성, 좌우 옆얼굴의 코·턱·귀·목 연결을 눈으로 합격 판정하지 못했다.
- **Native Live2D:** 실제 MOC3의 중립·±45°·요+피치·눈 감기·입 열기의 스크린샷에서 턱 아래 투명 틈·끊어진 목·떠 있는 귀/손·레이어 가림을 살펴야 한다. 색상/알파 합성과 접합 픽셀 검사만으로 완성 보증 불가능.
- **Native Inochi2D:** INP를 앱에서 실행해 목 루트/상하 가림, 파츠 부모 계층 및 실제 추적 입력을 확인해야 한다.
- **90° 측면:** PSD2Live 자동 ±45°는 90°가 아니다. 모드마다 추가 네이티브 키폼 제작과 검증 없이는 **미구현**으로 기록한다.
- **3D:** 생성 참고도와 실제 뼈/스키닝/메시 동일성은 별도 프로세스다. 3D HAIR/OUTFIT는 현재 미지원.
